 ### 📊 列表表头与表格 (Table Header & Content) - 🚨 排版核心

表格区域是信息展示的核心，表头 (`<thead>`) 具有特殊的布局要求：

#### 1. 表头样式 (`th` 样式)
* **背景色:** 品牌蓝 **`#4675dc`** 或与导航栏一致的蓝色，文字为纯白 **`#FFFFFF`**。
* **高度:** 约 `40px` - `45px`。
* **对齐:** 文本默认居中对齐 (Text Align Center)。

#### 2. 关键列的特殊排版 (Multi-line Columns)
官网表头不是简单的单行文本，必须强制换行：
* **出发站/到达站:**
    * 结构: 上一行显示“出发站”，下一行显示“到达站”。
    * 实现: 使用 `<br>` 换行或块级元素分行。
* **出发时间/到达时间:**
    * 结构: 上下分行显示。
    * **排序图标:** 右侧必须包含上下箭头图标 (Sort Icons)，表示可排序。
* **商务座/特等座:** 也是上下分行显示。
* **历时:** 包含一个向下的排序箭头。

#### 3. 表格内容行 (`tr`, `td`)
* **对齐:**
    * **车次号:** 左对齐 (Left Align)，并有一定左内边距。
    * **其他数据:** 居中对齐 (Center Align)。
* **车次号样式:**
    * 字体大且加粗 (如 `16px Bold`)。
    * **下划线:** 车次号下方可能有虚线或实线下划线。
* **站名排版:**
    * 必须也是**双行结构**：上方“出发站”，下方“到达站”。
    * 左侧可能有“始/过”小图标标记。
### 📊 列表表头与表格 (Table Header & Content) - 🚨 必须修正对齐

#### 1. 表头通用样式 (`thead > tr > th`)
* **水平对齐:** 所有表头单元格必须强制 **水平居中 (`text-align: center`)**。
    * *注意：之前的预览图中“出发站/到达站”是左对齐的，这是错误的，必须修正为居中。*
* **垂直对齐:** 垂直居中 (`vertical-align: middle`)。
* **背景色:** 品牌蓝 **`#3b99fc`** (参考官网截图)。
* **文字颜色:** 纯白 `#FFFFFF`。

#### 2. “出发站/到达站” 列的特殊样式
* **内容结构:** 依然保持双行显示（上行“出发站”，下行“到达站”）。
* **容器行为:** 无论内部使用 `div` 还是 `<br>`，其容器必须相对于单元格**水平居中**。

#### 3. “出发时间/到达时间” 列的特殊样式
* **对齐逻辑:** 文字部分居中，右侧的**排序箭头**紧随文字之后。
* **实现:** 使用 Flex 布局 (`justify-content: center`) 来保证“文字+箭头”作为一个整体在单元格内居中。

### 📊 表头与对齐规范 (Table Header Alignment) - 🚨 必须修正

为解决表头松散和未对齐的问题，请严格执行以下 CSS 规范：

#### 1. 表头单元格 (`th`)
* **布局模式:** 使用 `display: flex` + `align-items: center` + `justify-content: center`。这能确保内容绝对居中。
* **垂直间距:**
    * **行高 (`line-height`):** 必须设置得非常紧凑，建议为 **`1.2`** 或 **`18px`**。目前的间距太大是因为默认行高过高。
    * **Padding:** 适当减少上下内边距，例如 `padding: 5px 0`。

#### 2. 排序图标对齐 (Sort Icons Alignment)
* **容器:** 将“时间文字”和“排序箭头”放在同一个 Flex 容器中。
* **对齐:** `align-items: center`。
* **结构:**
    * 左侧: `div.text-group` (包含两行时间文字)。
    * 右侧: `div.icon-group` (包含上下两个小箭头)。
    * **关键:** 箭头必须垂直居中于这两行文字的右侧，而不是飘在上面或下面。

#### 3. 表格内容行对齐 (`td`)
* **双行对齐:** 必须确保“出发站”与“出发时间”在同一水平线上，“到达站”与“到达时间”在同一水平线上。
* **实现建议:** 每一列内部使用相同的 `line-height: 1.5`，确保行间距一致，从而视觉上自然对齐。

### 🔗 前后端集成规范 (Integration Specs) - 🚨 核心逻辑

前端将废弃本地 `mockData`，改为调用 Node.js 后端接口。

#### 1. 接口配置
* **Base URL:** `http://localhost:3000` (假设后端运行在此端口)
* **Endpoint:** `GET /api/tickets`

#### 2. 参数映射逻辑 (Frontend -> Backend)
前端的筛选组件需要将其状态转换为 URL 查询参数：

| 前端操作 | 逻辑转换 | 后端参数 (Query Param) |
| :--- | :--- | :--- |
| **基础查询** | 输入框值 | `from={城市名}&to={城市名}&date={日期}` |
| **车次类型** | 勾选 "GC-高铁/城际" | `filterType=G,C` |
| | 勾选 "D-动车" | `filterType=D` |
| | 勾选 "Z-直达" | `filterType=Z` |
| | 勾选 "K/T-快特" | `filterType=K,T` |
| **出发车站** | 勾选 "上海虹桥" | `filterStationIn=上海虹桥` |
| **到达车站** | 勾选 "北京南" | `filterStationOut=北京南` |
| **时间段** | 点击 "06:00-12:00" | `filterTimeStr=06:00-12:00` |

#### 3. 数据字段映射 (Backend Response -> UI)
后端返回的 JSON 数据是扁平结构的，渲染时需注意映射：

| UI 列名 | 后端字段 (JSON key) | 渲染逻辑 |
| :--- | :--- | :--- |
| **车次** | `train_no` | 直接显示，首字母用于判断颜色 |
| **出发/到达站** | `start_station` / `end_station` | **双行显示** (上出发，下到达) |
| **出发/到达时间** | `start_time` / `end_time` | **双行显示** |
| **历时** | `duration` | 显示如 "04:18" |
| **商务座** | `swz` | 显示 "有"/"无" 或数字。若为 "--" 则显示灰色横杠。 |
| **一等座** | `yd` | 同上 |
| **二等座** | `ed` | 同上 |
| **软卧** | `rw` | **注意：** 仅在普速车显示，高铁车显示 "--" |
| **硬卧** | `yw` | 同上 |

#### 4. 状态交互 (UX)
* **Loading:** 点击查询或筛选时，表格区域清空并显示 "正在查询..."。
* **Empty:** 若 `data.length === 0`，显示 "未找到符合条件的车次"。
* **Error:** 若请求失败，弹出提示 "网络服务异常"。

#### 5. 筛选逻辑防御规范 (Safe Filtering) - 🚨 修复白屏专用
**现状诊断：** 当前白屏是由 `toLowerCase()` 处理空值 (`undefined`) 引起的。
**执行要求：** 前端在处理筛选 (Filter) 和搜索 (Search) 逻辑时，必须严格遵守：

1.  **空值熔断 (Null Check):**
    在调用 `.toLowerCase()`, `.includes()` 等字符串方法前，必须先进行空值兜底。
    * ❌ 严禁裸奔: `item.train_type.toLowerCase()`
    * ✅ 必须穿甲: `(item.train_type || '').toLowerCase()`
    * ✅ 或者使用可选链: `item.train_type?.toLowerCase()`

2.  **字段对齐 (Field Alignment):**
    后端返回的字段名可能与前端预期不同（例如 `train_no` vs `trainCode`）。
    * 请在 `useMemo` 顶部打印 `console.log(item)` 确认字段名。
    * 如果字段不存在，应默认归类为 "其他" 或跳过，而不是报错。

3.  **渲染保护:**
    * 在最外层包裹 `Error Boundary` 或简单的 `try-catch` 块，确保即使数据处理出错，也能显示“数据加载异常”的提示，而不是白屏。
